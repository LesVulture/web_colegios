  <action>
Configurar Next.js para static export per decision del usuario:

1. **Actualizar next.config.ts** con `output: 'export'` y `images: { unoptimized: true }`:

```typescript
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: 'export',
  images: { unoptimized: true },
};

export default nextConfig;
```

El usuario decidio `output: 'export'` para garantizar 100% SSG. La investigacion confirma que esto requiere `images: { unoptimized: true }` porque la Image Optimization API no funciona sin servidor. Sin esta configuracion el build falla.

2. **Ejecutar `bun run build`** y verificar:
   - Todas las 59 rutas se generan exitosamente
   - Todas las rutas muestran `○` (Static) o `●` (SSG) — ninguna `ƒ` (Dynamic/lambda)
   - La carpeta `out/` se genera correctamente
   - Las rutas dinamicas `/uso/[slug]` y `/uso/[slug]/[fabricId]` se pre-renderizan para todos los params

3. **Verificar que las rutas dinamicas** tienen `generateStaticParams()` y `dynamicParams = false` (ya deberian estar configuradas desde Phase 4).

4. **Agregar `out/` al .gitignore** si no esta ya (el directorio de export no debe subirse al repo).

**NOTA sobre alternativa tecnica:** La investigacion recomienda deploy normal en Vercel (sin `output: 'export'`) para obtener image optimization gratis. Sin embargo, el usuario decidio explicitamente `output: 'export'` para 100% SSG. Implementar lo que el usuario decidio.
  </action>

  </verify>
