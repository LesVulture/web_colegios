```typescript
export function parseNumericWeight(weight: string): number {
  const match = weight.match(/^(\d+)/)
  return match ? parseInt(match[1], 10) : 0
}

export function parseNumericWidth(width: string): number {
  const match = width.match(/^(\d+)/)
  return match ? parseInt(match[1], 10) : 0
}
```

These extract the nominal number from weight strings like `"110 +-10 g/m2"` → 110 and width strings like `"151 +- 2 cm"` → 151. The `^(\d+)` regex works for all 31 fabrics (verified in research).

Note: The barrel export at `src/lib/content/index.ts` already re-exports all of helpers.ts via `export * from './helpers'`, so no barrel update needed.

**A. Create `src/components/filterable-fabric-grid.tsx`** — the complete 'use client' island component:

1. **Directive:** `'use client'` at top (CRITICAL for SSG preservation).

2. **Imports:** `useState`, `useMemo`, `useRef`, `useEffect` from react. `Fuse` from 'fuse.js'. `Search`, `X`, `ArrowUpDown` from 'lucide-react'. `FabricCard` from './fabric-card'. `TechIcon` from './tech-icon'. `TECHNOLOGIES` from '@/lib/content'. `parseNumericWeight`, `parseNumericWidth` from '@/lib/content/helpers'. `cn` from '@/lib/utils'. `Fabric` type from '@/lib/content/types'.

3. **Types:**
   ```typescript
   type SortField = 'weight' | 'width' | null
   type SortDirection = 'asc' | 'desc'
   ```

4. **Props:** `{ fabrics: readonly Fabric[], categorySlug: string }`

5. **State:**
   - `searchQuery` (string) — the debounced search value used for Fuse.js
   - `inputValue` (string) — the raw controlled input value (updates instantly)
   - `selectedTechs` (Set&lt;string&gt;) — selected technology IDs for filtering
   - `sortField` (SortField) — null | 'weight' | 'width'
   - `sortDirection` (SortDirection) — 'asc' | 'desc'

6. **Debounce logic:**
   - `useRef<ReturnType<typeof setTimeout>>(null)` for debounce timer
   - `handleSearchChange` updates `inputValue` immediately, then debounces `setSearchQuery` at 250ms
   - `useEffect` cleanup: clear debounce timer on unmount
   - When `clearFilters` is called, also clear `inputValue`

7. **Derived data (all useMemo, NO useEffect for derived state — per project skill `rerender-derived-state-no-effect`):**
   - `fuse`: `useMemo(() => new Fuse([...fabrics], { keys: ['name'], threshold: 0.4, ignoreLocation: true, minMatchCharLength: 2 }), [fabrics])`
   - `availableTechs`: Filter TECHNOLOGIES to only those present in this category's fabrics. `useMemo(() => { const techIds = new Set(fabrics.flatMap(f => [...f.technologies])); return TECHNOLOGIES.filter(t => techIds.has(t.id)) }, [fabrics])`
   - `filteredFabrics`: The main filtering/sorting pipeline in useMemo:
     1. If `searchQuery.trim().length >= 2` → use `fuse.search(searchQuery).map(r => r.item)`, else use `[...fabrics]`
     2. If `selectedTechs.size > 0` → filter with `f.technologies.some(t => selectedTechs.has(t))` (OR logic per research recommendation)
     3. If `sortField !== null` → `result.toSorted()` using parseNumericWeight or parseNumericWidth. Direction: `sortDirection === 'asc' ? va - vb : vb - va`
     Dependencies: `[fabrics, searchQuery, selectedTechs, sortField, sortDirection, fuse]`

8. **Handlers:**
   - `toggleTech(techId)`: toggle in/out of selectedTechs Set
   - `clearFilters()`: reset all state to defaults (searchQuery='', inputValue='', selectedTechs=new Set(), sortField=null)
   - `toggleSort(field)`: if same field, flip direction; if different, set field + 'asc'

9. **hasActiveFilters**: `searchQuery || selectedTechs.size > 0 || sortField`

10. **JSX structure:**
